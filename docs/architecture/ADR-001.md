# ADR-001: A deterministic synthetic application with one derived view

Status: accepted for the workshop.

## Context

The workshop needs a small genuine application whose behaviour and failures are repeatable without network services or production data. The original HTML deck and the Next.js application are separate entry points.

## Decision

Use Next.js App Router and strict TypeScript under `demo/`. Keep fixture data in `demo/src/data/events.json`. A server component loads the fixture and passes it to a client dashboard. Pure functions in `demo/src/lib/` perform filtering. The corrected view derives rows once and uses `rows.length` for the visible count. React state holds only the selected filter, never a separately synchronised count.

The UI does not fetch its own API. The read-only API demonstrates compatibility verification independently of UI rendering. MCP reads the same fixture and a fixed specification path. It has no write tools, credentials or arbitrary filesystem parameters.

## API v1

`GET /api/events?status=Degraded` returns HTTP 200 and:

```json
{
  "schemaVersion": 1,
  "synthetic": true,
  "events": [
    { "id": "EVT-007", "asset": "SYN-MEL-07", "region": "Melbourne", "status": "Degraded", "signal": "Elevated latency", "observedAt": "2026-10-21T00:36:00Z" },
    { "id": "EVT-008", "asset": "SYN-BAL-08", "region": "Ballarat", "status": "Degraded", "signal": "Packet loss", "observedAt": "2026-10-21T00:35:00Z" },
    { "id": "EVT-009", "asset": "SYN-BEN-09", "region": "Bendigo", "status": "Degraded", "signal": "Capacity warning", "observedAt": "2026-10-21T00:34:00Z" }
  ],
  "count": 3,
  "total": 12
}
```

Each object has exactly `id`, `asset`, `region`, `status`, `signal`, `observedAt`. Status is `Healthy | Degraded | Offline`. `observedAt` is a fixed ISO timestamp. Omitted status and `All` return all events. Unknown status returns HTTP 400 with `{ "error": "..." }`. Counts are numbers. No mutation endpoint exists.

## Verification and trade-offs

Vitest tests fixture distribution, empty collections, view invariants and API responses. Playwright tests the production build at a dedicated loopback port with server reuse disabled. Docker adds disposable filesystem execution, resource limits and disabled runtime networking. Browser contexts alone are not an OS sandbox. Initial image/dependency acquisition needs network access. An organisation still owns its runner isolation and access controls.

Fixed data keeps the workshop repeatable but does not exercise authentication, databases, external failure handling or operational scale. Those require separate architecture and tests before any real system adoption.
