# Specify the change

1. Read the feature specification, glossary and ADR. Identify the operator's observable outcome.
2. State the affected contract, source module and invariants. Separate global totals from the selected view.
3. Give examples for All, Healthy, Degraded and Offline, including an empty source for pure logic.
4. Name functional, keyboard, responsive and accessibility checks before editing.
5. Ask only for missing information that materially changes the implementation. Keep routine choices within the authorised scope.
6. Produce a short plan with acceptance criteria and an explicit verification command.

This is a locally authored teaching skill inspired by composable engineering procedures. It is guidance, not an independently enforced gate.
